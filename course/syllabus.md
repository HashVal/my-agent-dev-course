# Agent 开发：10 学时入门实践

版本：2026-10-23。状态：教学框架与资料映射已建立；学时长度及正式实践路线仍待校准。教学约定见 [AGENTS.md](../AGENTS.md)。

## 目标与预算

暂按 10 次 × 60 分钟安排。有基本 Python、命令行和 JSON 知识时，在教师提供骨架和小数据集的条件下，完成一个能调用工具、引用资料、记录轨迹并接受评测的小型 Agent。首次课确认基础；若按每学时 45 分钟计算或需要补编程基础，重新商定范围或增加课时。

贯穿项目为“本地学习资料助手”：对指定目录的少量 Markdown 文档进行检索和阅读，回答问题并给出来源；资料不足时说明缺口。先使用单 Agent、命令行和简单检索。

也可根据学习者已有项目，选取与 C01–C10 对应的实现切片作为实践材料。是否替换贯穿项目、哪些内容可以跳过，依据个人能力证据确认，不以代码存在代替掌握证明。

教学重点为 Agent 的实际开发、测试、调试与评测，用 SDK 调用、工具接线、状态传递及自动化验证连接原理；业务领域知识仅作为案例背景。项目实现覆盖与学习者个人能力分别记录。

每课参考节奏：回顾 5 分钟、讲解与演示 15 分钟、实践 30 分钟、验收与复盘 10 分钟。下表的资料用于教师准备及课内选段，不构成额外必读作业。完整阅读每篇博客通常另预算约 20–40 分钟，长文约 40–60 分钟，均为教学估计。

论文采用两层安排：主线只吸收与当课机制相关的片段，另设 [可选论文精讲路线](papers/index.md)。每课至多选一个论文片段，占原有讲解时间约 5–10 分钟；表中列出的多个来源供教师选择，不要求全部讲完。15 篇论文的完整映射和待验证问题见 [论文导读](resources/papers.md)。

## 主线课程

资源编号的原文、日期与状态见 [资源索引](resources/index.md)。每课只新增一个主要机制，沿用已有项目、样例和实验骨架。

| 课次 / 时间 | 学习目标与前置知识 | 实验及验收标准 | 教师选用资料 |
| --- | --- | --- | --- |
| C01 / 60 分钟 | 确认基础；区分模型、工具、工作流、Agent 与 harness。无需预先掌握框架。 | 画出本地资料助手的控制流；定义 3 个可核对的问题和最简单基线；说明什么任务不需要 Agent。 | R001、R003；R030 的架构概览仅作示意。 |
| C02 / 60 分钟 | 在 C01 基础上理解消息、token、上下文与结构化输出。 | 使用骨架完成一次模型请求；校验 JSON 及必需字段，检查一个格式正确但事实不成立的输出。 | R002；R037 / CoT 可作背景。实际接口使用上课时的官方 SDK 文档。 |
| C03 / 60 分钟 | 在 C02 基础上理解工具描述、参数、结果与执行权限。 | 实现指定目录内的阅读工具；比较含糊与清晰的工具描述；验证非法参数被程序拒绝。 | R004；R032 / Toolformer 说明工具能力的训练与推理使用的区别，不做模型训练。 |
| C04 / 60 分钟 | 在 C03 基础上理解工具反馈如何驱动下一步，以及谁决定停止。 | 实现“请求模型 → 校验并执行工具 → 回传结果”的循环；保存轨迹；验证正常完成和硬性步数上限。 | R031 / ReAct 解释行动与反馈；R030 的 turn/step 路径供后续对照，不要求安装 DSH。 |
| C05 / 60 分钟 | 在 C04 基础上区分上下文、运行状态、持久记录；理解压缩会丢信息。 | 比较完整工具结果与一种裁剪策略；准备答案在被裁剪部分的反例，记录输入量与回答变化。 | R005；R040 / MemGPT 选段解释上下文与外部记忆；R033 / Reflexion 的反馈记忆留给精讲。 |
| C06 / 60 分钟 | 在 C03–C05 基础上理解检索、证据与生成的分工。 | 加入简单关键词检索；保留文档标题/来源；分别检查没检索到证据和拿到证据却答错两类失败。 | R034 / RAG 与 R009。课内演示检索增强思想，原论文模型训练、混合检索和重排另行选读。 |
| C07 / 60 分钟 | 在 C04、C06 基础上选择固定工作流或动态循环。 | 对同一组问题比较固定“检索 → 回答”和 Agent 循环，使用相同模型和预算；解释收益与额外调用。 | R003；R033 / Reflexion 或 R038 / ToT 选一段用于讨论反馈或搜索的额外预算，完整实现放入论文线。 |
| C08 / 60 分钟 | 在 C01 的验收问题和已有轨迹上建立评测；区分 task、trial、grader、trace、outcome。 | 整理约 8–10 个案例，先定评分规则；检查来源和实际结果；区分任务失败、工具故障与环境失败，留少量案例做修改后的独立检查。 | R006、R016；优先用 R036 / τ-bench 解释结果状态。R044 / SWE-bench、R045 / AgentBench 为领域选读。 |
| C09 / 60 分钟 | 在 C03、C04、C08 基础上理解执行边界与故障处理。 | 用临时目录验证越权路径被拒绝；注入一段恶意资料测试边界；对模拟工具错误做有界重试并检查退出。 | R007、R022、R030；关联 R036 的规则遵守问题。文件工具实验不等于完整 OS 沙箱或 τ-bench 复现。 |
| C10 / 60 分钟 | 综合 C01–C09，解释完整系统和现有证据的局限。 | 展示可重复运行的项目、基线比较和至少一个失败案例；说明运行方式、预算、已知问题及下一步。 | R006、R030；R035 / SWE-agent 用于连接工具接口设计和 Harness 源码，完整比较见 P05。 |

课内不具备真实模型接口时，可以用模拟响应练习程序机制，记录“真实模型和端到端效果未验证”。环境安装或故障排查若占用实践时间，应调整安排，不能隐含要求课后补完必修任务。

## 资料如何支持教学

1. **工具设计要接受评测**：C03 不止写函数，还比较描述和返回内容能否帮助模型正确使用工具。
2. **上下文是每一步的输入设计**：C05 不把“更长历史”当作默认正确选择；C06 区分检索质量与回答质量。
3. **评测检查外部事实**：C08 不以“模型说完成了”为成功，也不把一条固定工具路径作为唯一正确答案。
4. **明确约束由谁执行**：C09 区分提示词提醒、工具层校验、人工/自动审批与 OS 隔离。每种机制只能声称自己实际覆盖的范围。
5. **用源码检查概念**：DSH 为循环、日志投影、工具拦截、裁剪提供真实案例；完整插件开发另设 X01。
6. **用论文检查论证**：主线理解机制，精讲分析方法、基线、消融和适用范围。不能把一个课堂实现或当前模型上的结果直接称为论文复现。

这些变化细化既有实验，不额外叠加必修工作。若课内比较实验超时，优先保留最小实现与验收，把第二种实现移入可选练习，并明确记录。

## 拓展路线

以下均不计入原 10 学时，也不要求全部完成。详见 [独立拓展章节](extensions/index.md)。时间为具备前置知识且环境可用时的估计。

| 章节 | 新增能力 | 前置要求 | 预计时间 |
| --- | --- | --- | --- |
| X01 | DeepSeek Harness / Cordis：插件、依赖、事件与生命周期 | C04、C05、C09；基本 TypeScript；接续已有 Cordis 学习记录 | 4–6 小时，可拆成 4–6 次课 |
| X02 | Skills：可复用流程与按需加载 | C03、C05、C08 | 1–2 小时 |
| X03 | MCP 与程序化工具调用（PTC） | C03–C05、C09；异步调用基础 | 2–3 小时 |
| X04 | 多 Agent：拆分、委派、合并与预算 | C07、C08；并发基础 | 2–3 小时 |
| X05 | 长期任务：持久化、交接、恢复与独立验收 | C04、C05、C08、C09 | 2–3 小时 |

DSH 源码掌握目标明显超出 10 学时入门课；若它成为主要学习目标，可把 X01 提升为下一阶段主线，再重新安排其他专题。基础设施、招聘评估和模型推理底层的文章保留在资料库，当前不设必修章节。

## 可选论文精讲

优先顺序为 **P01 ReAct → P02 Toolformer → P03 RAG → P04 Reflexion → P05 SWE-agent → P06 τ-bench**。每个单元暂排两次 60 分钟课：第一次解释问题与方法，第二次分析证据并做缩小版练习。六个单元共额外 12 学时，可按兴趣选择、在具备前置知识后穿插主线，不默认全部参加。

详细目标、前置要求、验收和其余九篇的选读安排见 [论文精讲路线](papers/index.md)。这里的预算覆盖引导式关键内容精讲和准备好骨架的小练习；逐段精读全文、补数学或训练基础、完整跑原论文实验另行估时。若与 X01–X05 共享练习，复用同一产出并记录实际耗时，不重复安排作业。
