# Agent 开发：10 学时入门实践

版本：2026-10-26。状态：教学框架与资料映射已建立，C00 分块导学已补充、初学者试读待执行；具体学时长度及实践安排由每位学习者开课时校准。教学约定见 [AGENTS.md](../AGENTS.md)。

## 目标与预算

暂按 10 次 × 60 分钟安排。有基本 Python、命令行和 JSON 知识时，在教师提供骨架和小数据集的条件下，完成一个能调用工具、引用资料、记录轨迹并接受评测的小型 Agent。首次课确认基础；若按每学时 45 分钟计算或需要补编程基础，重新商定范围或增加课时。

2026-10-23 建立 C00 基础知识地图，2026-10-26 补充 [四块导学讲义](lessons/C00-llm-foundations.md)。知识点与学习深度仍见 [prerequisite.md](../prerequisite.md)。首次学习先执行下方十题检查，再按知识缺口选择导学内容并衔接 C01。C00 复用 C01/C02 的相关内容，保留原 C 编号，不自动增加必修课时；具体教学节奏根据基线证据校准。

贯穿项目为“本地学习资料助手”：对指定目录的少量 Markdown 文档进行检索和阅读，回答问题并给出来源；资料不足时说明缺口。先使用单 Agent、命令行和简单检索。

也可根据学习者已有项目，选取与 C01–C10 对应的实现切片作为实践材料。是否替换贯穿项目、哪些内容可以跳过，依据个人能力证据确认，不以代码存在代替掌握证明。

教学重点为 Agent 的实际开发、测试、调试与评测，用 SDK 调用、工具接线、状态传递及自动化验证连接原理；业务领域知识仅作为案例背景。项目实现覆盖与学习者个人能力分别记录。

每课参考节奏：回顾 5 分钟、讲解与演示 15 分钟、实践 30 分钟、验收与复盘 10 分钟。下表的资料用于教师准备及课内选段，不构成额外必读作业。完整阅读每篇博客通常另预算约 20–40 分钟，长文约 40–60 分钟，均为教学估计。

论文采用两层安排：主线只吸收与当课机制相关的片段，另设 [可选论文精讲路线](papers/index.md)。每课至多选一个论文片段，占原有讲解时间约 5–10 分钟；表中列出的多个来源供教师选择，不要求全部讲完。15 篇论文的完整映射和待验证问题见 [论文导读](resources/papers.md)。

## 首次学习流程：十题基础检查

课程入口遵循：**读取已有基线 → 首次组卷或继续未完成试卷 → 学习者作答 → AI 判定并保存个人基线 → 按缺口纠错或进入 C00 学习块 → 用新情形复核 → 共同案例衔接 C01**。本流程与 [AGENTS.md](../AGENTS.md) 的首次学习规则共同适用。

### 1. 确认是否已有适用基线

读取 prerequisite.md、本地 `baseline-status.md`（若存在）及学习记录。若当前学习者已有完整检查，直接从记录的下一步衔接，不自动再考十题；若记录未完成，继续原试卷。切换学习者时保留旧记录于 `.local/`，不能用其他人的掌握情况作为当前基线。

规则建立前已完成的首次测试按真实题源归档为历史基线，可以用于衔接；不能伪装成新规则的混合试卷。文件缺失且没有已完成检查的证据时，执行下面的首次组卷流程。

### 2. 五道题库题，加五道模型生成题

1. 从 [prerequisite-baseline-quick-check.md](../prerequisite-baseline-quick-check.md) 的 B01–B10 选择五道不同题目，按知识范围选择，保留稳定题号。不要默认只取前五题。
2. 建立覆盖表，逐题列出 prerequisite 小节及实际考点。先记录这五题没有考察的范围，再由当前模型生成 G01–G05 补齐。
3. 每道生成题至少增加一个前五题未考察的考点；不能复制题库剩余题目或只改变量名。允许综合题复用已有概念作为背景，但评分重点应覆盖新增知识。
4. 十题整体应覆盖 §2.1–§2.7 七组概念，并包含部分 §3 编程、接口或环境基础。十题无法覆盖全部细项时，明确保存未检查范围；§5 可选深入内容不列为必考。
5. 出题时一并确定每题 0–2 分的评分依据，保留动态题实际题干和评分要点，避免见到答案后临时改变要求。只向学习者展示题干、作答方式和评分说明，参考答案用于判定。
6. 依照 [题库的出题审查](../prerequisite-baseline-quick-check.md#题干清晰度与诊断边界) 检查术语、场景与条件。位置题区分提示词和输出、预测目标和已有位置，attention 题限定模型类型；不将矩阵或架构实现变成入门必考。

组卷记录使用以下结构；生成题必须写出具体考点，不能只写“补基础”。

| 当次序号 | 来源与题号 | prerequisite 小节 | 实际考点 | 相对前五题新增范围 |
| --- | --- | --- | --- | --- |
| 1–5，各自一行 | 题库 Bxx | 对应小节 | 具体机制或行为 | 不适用 |
| 6–10，各自一行 | 当前模型 G01–G05 | 对应小节 | 具体机制或行为 | 必填；与已选五题对照 |

### 3. 作答与 AI 判定

- 告知预计答题 15–25 分钟，可以一次回答或逐题回答。说明测试用于安排学习，允许回答“没接触过这些术语”；无需猜答案。不确定可说明；使用资料或其他辅助时记录条件，未知时不假定闭卷。
- AI 逐题给分并解释依据：2 分为核心判断和机制正确，1 分为部分正确或关键解释不足，0 分为核心错误或明确不了解。未作答记“未检查”，与 0 分分开；未完成时仅报告已答题得分，不声称整套检查完成。
- 对含糊回答先澄清。接受合理的替代解释和实现方案，不因没有背出术语或框架 API 而机械扣分。
- 区分“题干指代不清”“术语陌生”和“对机制有错误认识”。只澄清场景时记录澄清内容；若讲解了待测机制，保留首次表现并将之后的回答标为有辅助，不能当作独立初测。
- 评分后指出具体缺口，并区分“首次回答正确”“反馈已讲解”“补充点已复核”“独立实践已验证”。不把模型讲解算作学习者已经掌握，不把十题总分当作各知识点的完整认证。

### 4. 保存 baseline-status.md

判定后在课程根目录生成或更新本地 `baseline-status.md`。作答未完也可保存进度，但须标记为未完成，保留当次试卷。至少记录：

| 信息组 | 必需内容 |
| --- | --- |
| 元数据 | 日期、题库/知识清单版本、组卷方式、完成状态；出题/判定模型标识、答题条件和实际耗时，无法确认时写未知 |
| 试卷来源 | 五道 B 题号及版本、五道生成题的完整题干与评分依据；若为历史试卷，保留其真实来源 |
| 逐题证据 | 原始回答、得分、AI 判定理由、对应知识点；答题歧义或判定不确定性单独说明 |
| 知识状态 | 有概念证据、部分理解/待补充、明确不了解、未检查；补充区分术语陌生与具体误解，不从单个考点推断整块掌握；实践证据单独记录 |
| 教学安排 | 知识缺口对应的 C00 学习块与选学理由、尚未覆盖的范围、已反馈但未复核的点、下一次起点与需确认的环境或预算 |
| 后续变化 | 复习和实操日期、实际操作与结果、状态变化；不覆盖原始答案和首次判定 |

题库题可通过稳定题号与固定版本引用；题干改编或题库版本无法固定时保存当次全文。生成题必须保存全文，不能只写标题或模型“已出题”。

此文件由 `.gitignore` 忽略；提交前确认不在 Git 索引中。题库、进度和大纲不复制个人答案、分数或诊断，也不添加指向该忽略文件的公共 Markdown 链接。需要保留旧版时使用已忽略的 `.local/`；禁止强制提交个人基线。

### 5. 按知识点安排后续学习

AI 初次判定与反馈预计 5–10 分钟，用于解释诊断和选择学习块；需要展开的纠错计入下方 C00 导学。答题、反馈与导学共同计入 C01/C02 原有预算，不重复计时。按具体考点安排内容，不要求在检查后再完整重讲全部内容，也不能只报告正确答案就进入 C01。

纠错深度可参照 [虚构回答与示范反馈](../prerequisite-baseline-quick-check.md#测后反馈与纠错示例)：解释具体误解、正确机制与原因，用例子帮助理解，再提供追问方向和新情形复核。下面的 C00 流程决定补哪一块，本节示例说明如何把局部误解讲清楚。

不同动态试卷难度可能不同，总分用于各自的教学诊断。进入 C02/C03 前，还需按实际需要确认 Python 环境、可用模型接口和费用预算，不能从概念答题推断这些条件已经具备。

## C00 基础导学与 C01 衔接

### 按知识缺口选择内容

讲义为 [从一次资料问答认识 LLM](lessons/C00-llm-foundations.md)，沿用一套讲义，不另设教师版。下面的映射按实际考点使用，B 题仅为定位示例，不能替代当次 G 题的覆盖表。

| 学习块与范围 | 可能的诊断证据 | 进入内容与后续用途 |
| --- | --- | --- |
| 一：模型与应用；§2.1 | B01 或生成题中混淆文件存在与模型收到内容 | 追踪输入路径，接 C01 数据流与方案比较 |
| 二：文字如何生成；§2.2、§2.4 | B02/B03/B05 或生成题中 token、生成、向量或 attention 陌生 | 建立逐步生成和信息融合直觉，接 C02 输入输出；不扩成 Transformer 实现课 |
| 三：信息与记忆；§2.3、§2.5 | B04/B06 或生成题中混淆权重、上下文与外部记录 | 解释信息存放和进入请求的路径，接 C02/C05 |
| 四：从生成到完成任务；§2.6、§2.7 | B01/B07/B08 或生成题中混淆请求、执行与证据 | 解释工具反馈和外部验证，接 C01 验收及 C03/C04 |

同一题可能涉及多块，只定位已经观察到的缺口。Python、JSON、HTTP 等 §3 能力单独标记并在相应实验前确认，不能用 C00 概念讲解替代编程实践。

| 当前证据 | 下一步 | 记录边界 |
| --- | --- | --- |
| 能解释相关机制 | 简短回顾该块与共同案例的关系，进入尚有缺口的内容 | 概念证据不代表独立实现能力 |
| 有局部误解 | 指出具体误解，解释原因，用一个例子或反例纠正，再用新情形复核 | 不将同一缺口在多道错题下重复讲授 |
| 一组核心概念明确陌生 | 从对应学习块开头连贯讲解，按“问题 → 解释 → 例子 → 检查”推进 | 不要求靠逐题正确答案自行补齐概念 |
| 未作答、未覆盖或题意仍不清 | 先澄清或使用该块已有的简短检查确定起点 | 保持“未检查”，不直接判为不会或跳过 |

**虚构纠错示例：**学习者说“已经读取文件，所以模型肯定知道内容”。先肯定其中可确认的事实仅为“读取完成”，再指出遗漏的是传递步骤：读取结果可能只留在程序变量里；只有把内容放入模型请求，才有机会影响生成。用“打印了原文，但请求只发出文件名”作反例。若学习者连请求与模型都不熟悉，先讲第一块；若只是漏想传递步骤，直接用第一块的会议记录问题复核即可。可继续追问的具体方向是“怎样检查实际发出的输入包含原文”，并在 C01/C02 的请求预览中验证。

每块讲完使用讲义末尾的新情形，依据 [复核口径](evals/C00-readthrough.md#理解检查口径) 判断能否解释信息与状态变化，不要求背术语，也不把原题复述作为充分证据。初次答案、纠错/讲解、复核题与回答、辅助条件、尚存困难分别追加到本地 baseline-status.md，保留历史。未通过则定位到具体段落补充，不自动开启另一套十题测试。

### 课时如何复用

下面是两种**待实课校准的候选排程**，均暂按 C01/C02 合计 120 分钟。不是在两次课之前额外加一节 C00，也不是对完成时间的保证。

| 环节 | 基础已有证据，仅局部补充 | 多块概念陌生 |
| --- | --- | --- |
| 十题作答 | 20 分钟 | 20 分钟 |
| 初次判定、反馈与选学 | 5 分钟 | 5 分钟 |
| C00 讲解、纠错、块内复核及共同案例 | 10 分钟 | 40 分钟 |
| C01 方案、验收设计与最小基线 | 40 分钟 | 25 分钟 |
| C02 消息与结构化输出实践、验收 | 45 分钟 | 30 分钟 |
| 合计 | 120 分钟 | 120 分钟 |

40 分钟导学可暂分为：第一块 6、第二块 14、第三块 8、第四块 8、共同案例衔接 4 分钟，各块含简短理解检查。若多块都需重新讲解，40 分钟可能不足；如实记录，不因时间到就宣布通过。

C00 已讲过的生成、训练与上下文概念，在 C02 通过消息和实际输出回顾，避免重复完整讲授；缓存公式等可选内容不占必修时间。C01/C02 使用已有小数据与骨架，仍保留各自核心验收。已有完整基线时省下的测试时间归还讲解与实践，不重复测试来填满排程。

若实际作答用到 25 分钟、反馈用到 10 分钟，或环境准备与实验超出剩余时间，就重新核算总预算。优先减少重复讲解和可选展开；若仍无法完成核心验收，列明未完成项并与学习者商定缩小范围或增加时间。不得自动压缩核心验收、占用后续必修课或转成课后作业。

### 进入 C01 的共同产出

沿讲义中的 limits.md 问答画出“程序读取 → 组织输入 → 模型生成 → 对照来源”的路径，再讨论资料不足的问题。进入 C01 时复用这张图，比较谁决定下一步，并定义可检查的任务结果。短资料可以先做简单方案；资料数量或任务要求变化时，再考虑检索和按需工具。对这种取舍的理解通过解释来核查，不要求给出唯一方案。

C00 的阅读与解释不替代 C01 的可运行基线，也不要求提前完成 C03/C04。内容试读办法与待验证项见 [C00 试读与衔接核查](evals/C00-readthrough.md)。没有真人试读记录时，不能把作者自检或 AI 模拟回答写成学习效果验证。

## 主线课程

资源编号的原文、日期与状态见 [资源索引](resources/index.md)。每课只新增一个主要机制，沿用已有项目、样例和实验骨架。

C01 讲义见 [Agent 基础与任务定义](lessons/C01-agent-basics.md)，包含控制流比较、基线选择和验收设计练习，并分别列出 [内容引用](lessons/C01-agent-basics.md#引用) 与 [可选深入阅读](lessons/C01-agent-basics.md#深入阅读与观看)；[课程实验](labs/C01-baseline/README.md) 提供单次调用骨架、虚构资料和三题评分参考，使用原有实践预算，必要时与 C02 统筹。

C02 讲义见 [模型交互与结构化输出](lessons/C02-model-interaction.md)，覆盖消息历史、两层 JSON、数据契约、token 预算与失败分层；[实验骨架](labs/C02-structured-output/README.md) 与 [验收参考](evals/C02-structured-output-cases.md) 供独立作答和核查。KV cache 的机制说明帮助区分计算复用和上下文长度，完整推理引擎实现不列为必修。首次学习时与 C00/C01 按上方候选排程共用原 120 分钟；已有基础时使用原单课安排。个人成绩不写入公共大纲。

C02 的 [引用](lessons/C02-model-interaction.md#引用) 与 [深入阅读](lessons/C02-model-interaction.md#深入阅读) 分开列出，标明官方接口依据、论文选段、未精读部分和可选时间；新增 R047–R052 的状态见资源索引。R052 只在本课引出评判器局限，完整评测讨论留到 C08。

## 资料如何支持教学

1. **工具设计要接受评测**：C03 不止写函数，还比较描述和返回内容能否帮助模型正确使用工具。
2. **上下文是每一步的输入设计**：C05 不把“更长历史”当作默认正确选择；C06 区分检索质量与回答质量。
3. **评测检查外部事实**：C08 不以“模型说完成了”为成功，也不把一条固定工具路径作为唯一正确答案。
4. **明确约束由谁执行**：C09 区分提示词提醒、工具层校验、人工/自动审批与 OS 隔离。每种机制只能声称自己实际覆盖的范围。
5. **用源码检查概念**：DSH 为循环、日志投影、工具拦截、裁剪提供真实案例；完整插件开发另设 X01。
6. **用论文检查论证**：主线理解机制，精讲分析方法、基线、消融和适用范围。不能把一个课堂实现或当前模型上的结果直接称为论文复现。

这些变化细化既有实验，不额外叠加必修工作。若课内比较实验超时，优先保留最小实现与验收，把第二种实现移入可选练习，并明确记录。
