# C07：固定工作流与动态选择

C06 已能根据词项找到片段。现在遇到问题“A17 的专用额度是多少”：第一次检索可能只找到 A17 对应代号 QH-Z9，而额度写在另一份文档里。我们可以让程序预先规定再查一次，也可以让模型根据返回内容选择查询。两者都能形成多步过程，区别在于下一步的决定来自哪里。

本课解决的问题是：**什么时候值得让模型多作一次行动选择，它带来的收益能否抵消额外请求和失败机会？** 前置是 C04 的有界循环和 C06 的检索函数。你要实现固定流程，把它与全文输入和 Agent 放在相同资料、问题、输出契约下比较，并依据实际轨迹说明选择。

## 三个方案在做同一件事

**全文输入**由程序一次把六份资料提供给模型，再请求一个回答。它沿用 C01 的比较思想，但此处使用统一的 JSON 输出规则和扩充资料，不能直接拿旧 C01 日志当成同条件对照。

**固定工作流（workflow）**先用原问题检索一次，再把结果送给模型回答。检索词、检索次数和回答时机由程序规定；即使模型觉得缺少另一份资料，这条流程也不会自动追加行动。这不是缺陷的定义，而是一种明确的复杂度与覆盖范围选择。

**Agent 循环**由模型在已注册的工具里选择检索或阅读，看到结果后决定继续还是回答。程序仍负责参数校验、权限、消息关系和停止上限。模型可能发现第一批证据已经够用，也可能沿代号继续查。它也可能走错方向、重复读同一文件，最后耗尽预算。

| 方案 | 进入生成前的信息来源 | 下一步由谁选择 |
| --- | --- | --- |
| all | 全部固定资料 | 程序直接进入回答 |
| fixed | 原问题的一次 top-3 检索 | 程序直接进入回答 |
| agent | 模型请求的搜索或阅读结果 | 模型提议；程序检查并执行 |

“有两步”不等于 Agent，“只有读操作”也不等于无需 Agent。资料只有六份时，全文基线很可能足够。是否需要动态查询，应由资料规模、信息依赖、实际错误和成本决定，不能仅由有没有写文件推出。

## 规划就是选择如何获得还缺的信息

规划（planning）容易被理解成先生成一长串步骤。本课把它缩小到可观察的决定：已经知道什么，还缺什么，下一次行动能不能补上这个缺口。

例如第一次结果是“归档任务 A17 的额度规则以代号 QH-Z9 登记，请查阅 quota.md”。接下来可以搜索 QH-Z9，也可以直接阅读 quota.md。两条路径都可能正确，评测不应强迫模型模仿某条唯一轨迹；要检查它是否得到足够证据、没有越过预算，并给出适用范围正确的答案。

这里没有要求模型公开隐藏推理。工具名、参数、结果和最后答案已经足以检查行动是否利用了反馈。若模型第二次仍搜索与代号无关的词，可以从行为讨论其问题，无需把一段自述“我在认真规划”当成证明。

固定流程也能处理这个例子，比如程序明确识别代号再查一次。代价是多写一条适配规则，而且遇到其他依赖形式可能还需要新分支。因此比较重点是维护与覆盖取舍，而不是给固定流程贴上“不能推理”的标签：它最后的模型调用同样可以组合和推导证据。

## 公平比较需要固定什么

假设 Agent 运行四次模型请求，固定流程只运行一次，Agent 得分更高。这个观察说明该系统在这次预算配置下表现较好，却不能推出模型本身更强。额外查询带来了更多证据和推理机会，也改变了延迟与费用。

本实验固定问题、资料版本、输出要求、模型和采样配置，并为所有方案提供相同最高预算：4 次模型请求、3 次工具分发、3 次实际工具尝试。固定流程通常只用 1 次模型和 1 次搜索，全文输入只用 1 次模型。共同上限保证比较的资源边界一致，实际使用量仍必须报告，不能为了凑相同次数给简单方案空跑。

如果以后比较“相同实际请求数下谁更好”，那是另一个实验，需要重新定义方案。课堂先报告结果和资源消耗，避免把不同问题混在一个结论里。

请求记录还保存每次 `usage` 和端到端耗时。多个调用的 token 用量需要按调用求和；某次请求的累计历史不能通过只看最后一次响应代表全任务成本。缓存与服务波动使单次延迟不稳定，温度设为 0 也不意味着运行一定完全可重复。

## 从程序轨迹看出差异

一种可能的人工示意轨迹如下；它不是实际模型输出：

```text
fixed：search(原问题) → 得到 A17 与 QH-Z9 的关系 → 请求模型回答
agent：请求模型 → search(A17) → 反馈 → 请求模型
       → read(quota.md) → 反馈 → 请求模型 → 回答
```

第二条路径有三次模型请求、两次工具分发。第一条只有一次模型请求，但输入可能缺少专用额度。要确认这种差异真的发生，必须看实际返回的 top-3；检索器也可能第一轮就同时找到两份材料。不要把示意路径当作必然优势，更不要写死答案来制造 Agent 的胜利。

工具额度耗尽时仍沿用 C04 的规则：只要模型请求额度还有余额，可以得到最终回答；如果再次请求工具，程序拒绝执行。正常停止只表示收到了回答，C02 的字段校验和事实核查仍然需要进行。

## 动手实验

按 [lab README](../labs/C07-workflows/README.md) 完成 `run_fixed`，只连接“一次搜索 → 一次回答”。公共运行器已提供与 C03/C04/C06 的接线，Agent 路径调用你自己的 C04 `run_loop`。可选接入 C05 投影器，但基础对照先使用完整历史；否则同时改变策略与输入，很难解释差异。

| 操作 | 要观察的内容 |
| --- | --- |
| 预览 all/fixed/agent | 问题和规则相同，初始证据及工具暴露不同 |
| 运行离线接线示例 | 请求中是否包含正确工具结果，计数与状态是否一致 |
| 对 E01、E07 作同题比较 | 最终答案、必要证据、请求次数、工具尝试、耗时 |
| 分析一次失败 | 是证据未找到、证据未利用、协议错误还是预算耗尽 |

模拟模型只按约定返回行动与占位回答，不能用它得出哪个方案的语言能力更好。真实对照需显式 `--send`，课内默认选两题、每种方案一次，最多 12 次请求；若要把 Agent 的全部 4 次上限用满，两题三方案的理论上限就是 12 次，不自动重复挑选最佳结果。

## 复盘与下一课

新情形：固定流程在 2/2 题中正确且更快，Agent 在其中一题重复读取而失败。合理结论是保留本任务的简单方案，记录 Agent 的失败；不是改评分口径让复杂方案显得有价值。两题也不足以支持普遍结论，C08 会把问题种类扩展成小型诊断集。

完成 [验收](../evals/C07-workflows-cases.md) 时，提交给老师的是“在这些输入和预算下，观察到什么，为什么暂时选这个方案”的解释。没有实际数据时写待验证，不先替实验下结论。
