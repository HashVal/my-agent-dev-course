# C06：检索、证据与生成

C05 说明了一个问题：按文本位置裁剪，可能删掉唯一有用的句子。要按问题选择信息，就需要先从资料中找出候选证据，再交给模型回答。这是本课的出发点，不是为了给小项目强行加一个向量数据库。

本课要解决：**没有全文进入输入时，怎样找到可引用的资料，并判断失败发生在检索还是回答阶段？** 前置是 C03 的只读工具、C05 的上下文选择，以及 Python 集合和排序。验收需要实现关键词检索，保留来源与原文，展示命中和未命中的例子，并能定位两种不同失败。

## 为什么先检索，再生成

检索增强生成（retrieval-augmented generation，RAG）在这里指：程序先取得外部资料的相关部分，再让语言模型根据这些资料生成回答。检索器决定哪些证据进入本次输入，生成模型决定怎样组织结论。原始 RAG 论文有自己的模型与训练方法；本课只实现这条信息路径，不复现原论文训练。

```text
问题 → 检索资料 → 带来源的候选片段 → 模型回答 → 核查结论与引用
           ↑                                  ↑
     证据有没有进来？                    结论是否由证据支持？
```

例如“任务 T01 还剩几次额度”需要两件事：当前已经调用几次，以及上限是多少。只检索到上限，模型无法凭这段资料知道 T01 已用多少次。即使引用的句子真实存在，也可能不足以支持完整结论。反过来，两段都已给模型，它仍可能把 `3-2` 算错；这时继续调整检索器未必解决问题。

当所有资料都短小且可放入上下文，C01 的全文基线仍值得保留。检索引入新的漏检风险。我们选择增加检索，是为了学习信息筛选与失败定位，并为后续比较提供一种候选方案；是否改善效果，要到同题对照中判断。

## 从文件变成可核查的片段

检索的单位不一定是整个文件。把文档拆成较小片段，能让模型少读无关内容，但拆开之后可能丢掉主体。例如单独一句“最多允许 5 次”没有告诉你适用于谁。若把它误套到 T01，引用是真的，适用范围却错了。

本课按非空段落分块，每个片段带 `file`、`title`、`start_line`、`end_line` 和 `quote`。行号从 1 开始，首尾都包含。标题帮助检索与解释语境，`quote` 则保持正文原样，不把标题或老师补充的解释伪装成原文。

```json
{
  "file": "quota.md",
  "title": "QH-Z9 专用归档规则",
  "start_line": 5,
  "end_line": 5,
  "quote": "代号 QH-Z9 的归档任务最多允许 5 次工具调用。"
}
```

这个片段能支持 QH-Z9 的规则，不能单独证明 A17 属于 QH-Z9。另一份 `routing.md` 提供映射关系，两个文件结合才构成完整依据。原文行号也依赖资料版本：后来在文件头插入一行，旧行号就变了，所以运行记录还应保留当时使用的资料快照。

## 用一个朴素检索器建立比较基线

教师代码把英文、编号提取为词，把连续汉字拆成相邻双字片段。例如“工具调用”得到“工具”“具调”“调用”。这是为了避免仅靠空格分词导致整句中文成为一个词；它不是成熟中文分词，也不理解同义词。

检索分数定义为问题与“标题加正文”共享的不同词项数量。问题词集合是 `{T01, 工具, 调用}`，某片段包含 `{T01, 调用, search}`，交集有两个，分数为 2。重复写十次 T01 不增加分数，因为我们使用集合。分数只是字面匹配程度，不是答案正确的概率。

筛去零分片段，再按分数从高到低排列。同分时用文件名和起始行号排序，使同一个输入每次得到可复核的顺序。最后取前 k 条，这就是 `top_k`。k 小能减少输入，却可能漏掉组合问题所需的第二段；k 大可能带入相似但不适用的规则。调 k 是取舍，不能把“有返回”当作找到了充分证据。

如果找不到共享词项，返回空数组。不要为了让流程显得顺利，随便把第一篇文档补进去。空结果清楚暴露了信息缺口；伪装的候选会使后续更难判断发生了什么。

## 未命中并不等于知识库没有答案

这是最需要检查的推理边界。“花了多少钱”可能没有字面命中任何费用资料：原因可能是资料根本没有价格，也可能是资料写成“结算金额”，朴素检索器不识别同义词。仅凭一次空结果，不能断言整个知识库没有答案。

面对这个失败，先检查资料中是否实际存在支持答案的原文。如果存在而没有被选中，属于检索失败；如果不存在，则应说明资料不足。另一个问题是检索命中了相邻主题但不含答案，例如工具调用次数不包含每次调用的价格。返回若干高分段落仍不足以计算费用。

如果候选包含完整证据，模型却引用了另一个任务的记录，问题位于生成或证据使用阶段。C08 会把这些原因纳入评测。本课先用人工核对把问题定位清楚，暂不让另一个模型替我们宣布“检索成功”。

## 动手实验

打开 [实验说明](../labs/C06-retrieval/README.md)。资料由 C01 三份短文加三份虚构材料组成，检索只读固定文件名单，评测答案不在检索目录中。教师代码提供分块与词项处理，你只实现 `search`。

| 动作 | 观察依据 | 这个观察不能证明什么 |
| --- | --- | --- |
| 查“单次任务 工具调用” | 分数、排序、来源行号 | 排第一不代表所有问题都由此回答 |
| 查“T01 工具调用上限”并改 k | 是否同时保留任务记录和规则 | 输入片段更多不保证模型更准 |
| 查一个完全不匹配的词 | 返回空数组 | 不能仅据此判断整个资料库无答案 |
| 查“A17 专用额度”，再查返回的代号 | 第一轮与第二轮得到不同证据 | 这两次手工查询不是实际 Agent 决策 |

先预测一个同分情况下的顺序，再运行检查。然后核对 `quote` 是否等于源文件对应行，而不是根据片段大意判断“差不多”。本课脚本只执行检索；下一课统一接模型，避免为每种检索试验反复付费。

分层提示：先为每个 chunk 计算词项交集；再处理正分过滤与稳定排序；最后做参数校验和来源不变检查。不要针对 E01、E02 的题号写特例，否则你测到的是题库记忆，而不是检索机制。

## 复盘与下一课

新情形：模型回答 T02 的额度时引用了 `quota.md` 中真实的 5 次规则。你需要检查“这句话是否存在”，还需要检查“这条规则适用于哪个对象”。请说明缺少哪一类证据，以及应该回查检索结果还是纠正生成过程。

完成 [验收](../evals/C06-retrieval-cases.md) 后，把搜索函数作为工具接入 C07。固定工作流会使用原问题检索一次；Agent 可以利用第一轮找到的代号再查。这样的设计让我们有具体理由比较两种执行策略，而不是先认定多步一定更聪明。
