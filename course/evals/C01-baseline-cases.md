# C01：资料问答最小验收集

本文件是 [C01 实验](../labs/C01-baseline/README.md) 的公共题目与评分参考，不包含任何学习者的实际结果。先尝试 [讲义中的验收设计](../lessons/C01-agent-basics.md)，再对照本参考，在调用模型前固定判定口径。

## 共同任务与输入

被测系统接收一个问题和三篇资料，依据资料回答、标注文件名及支持结论的原文或可定位片段；资料不足时说明缺少的信息。资料中的工具记录是被问答的内容，不是被测系统必须执行的动作。

输入固定为 [rules.md](../labs/C01-materials/rules.md)、[limits.md](../labs/C01-materials/limits.md)、[trace.md](../labs/C01-materials/trace.md)，均为虚构资料。全文基线每题独立调用一次回答模型，不让前一题的回答或评分参考进入后一题输入。预期答案和评分说明仅供评测，不提供给被测模型。

## C01-E01：单处证据

**问题：**一次任务最多允许执行多少次工具调用？

**预期行为：**回答最多 3 次，并引用 limits.md 中“单次任务最多执行 3 次工具调用。”

**通过标准：**数字正确，且文件与证据匹配。不要求逐字匹配某个回答模板；只答“3 次”但缺少来源时，事实正确、来源要求不通过。

## C01-E02：组合两份资料

**问题：**根据现有记录，T01 是否已经达到工具调用上限？

**预期行为：**尚未达到。limits.md 规定上限为 3 次，每次 search/read 各消耗 1 次；trace.md 记录一次 search 和一次 read，且无其他调用。因此已用 2 次，低于上限 3 次。

**通过标准：**结论正确，说明两次调用如何与三次上限比较，并引用 limits.md 与 trace.md 的相应依据。仅答“没有”而没有依据不满足完整要求。

**边界口径：**“达到上限”指已用次数大于或等于上限；“超过上限”指严格大于上限。题干使用“达到”消除“撞限制”的歧义。本例已用次数为 2，两种判断均为否；不将本例结果推广为边界值测试已经通过。

## C01-E03：资料不足

**问题：**T01 目前花了多少钱？

**预期行为：**明确说明无法从这三份资料确定金额。trace.md 仅记录工具类型与次数，没有实际收费金额或模型 API 的计费用量；另外两份资料也未提供计费规则。

**需要补充的信息：**先明确费用范围，例如只计算模型 API 费用，还是还包括收费工具或其他资源。若自行计算模型 API 费用，需要适用的计费规则及实际计费用量，模型/服务与价格版本等信息用于匹配费率；也可使用能对应到 T01 的实际账单或费用记录。不能把工具调用次数直接换算成模型请求次数或 token 用量。

**通过标准：**不捏造金额，不断言零费用，明确指出实际费用记录缺失，或同时指出计费规则和实际用量不足。接受等价解释，不强求枚举所有可能的计费项目。若只说缺少价格文档，拒绝给金额的判断正确，但缺口说明不完整。

**来源要求：**可引用 trace.md 说明目前记录了哪些信息，并说明给定全部资料未提供费用依据；不能编造一个“价格文件”作为已存在的来源。资料不足是对这组输入的判断，不是对现实中是否存在账单的判断。

## 判定与本地记录

每题分别检查“结论/行为”“引用依据”“必要说明”，三项全部满足才判为该题通过；按含义判定，不进行完整答案字符串匹配。来源要求也适用于资料不足的回答：引用实际存在的相关信息，说明给定资料的范围；不能为缺失内容编造引文。记录具体失败维度，不能用格式正确或请求成功替代事实与来源核查。

运行记录至少包含模型标识、实际提示词与输入资料、请求参数、输出、评分依据、用量和耗时。模型精确版本、费用或其他未获取字段写未知。

修改提示词后保留旧输入和旧结果，先复查失败题，再检查原来通过的题；不混用不同版本的成绩。若调整评分标准，单独记录原因与版本，不为了让已有输出通过而临时放宽要求。

这三个样例用于小规模调试与回归，不能用一次通过宣称普遍可靠。它们参与过修改后，也不能当作独立的未见样例评测。后续比较全文输入与固定检索时，使用相同问题、资料、回答模型和评分要求，并记录检索是否提供了必要证据。
