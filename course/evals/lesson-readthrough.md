# C01–C04：讲义可读性与实验衔接试读

本文件用于检查讲义是否让读者理解核心机制、知道实验要验证什么。它不增加课程练习，也不代替各课已有的程序与业务验收。每次试读只选当前要学的一章，复用该课的回顾或收尾时间；不把四章全部试读变成必修任务。

## 试读怎样进行

先依据已有学习记录确认前置知识。请读者读到当课实验入口，用自己的话说明本章解决的问题、核心机制以及一次操作的预期结果。卡住时先记录具体词句，再解释；复核时记录是否得到提示。不要要求先完整阅读所有参考资料。

以下问题用于试读和复盘，可以替换当课同类理解检查，不在原安排之外追加：

| 章节与入口 | 可以使用的新情形 | 观察依据 |
| --- | --- | --- |
| [C01](../lessons/C01-agent-basics.md#输入组装练习) | 固定程序总是先搜一次再回答，另一个程序允许模型根据结果选择再读文件。怎样区分控制分工？为什么实验要先看请求预览？ | 能沿步骤指出决策来源，并解释预览检查的是实际输入；知道运行后还需按预先规则核查 |
| [C02](../lessons/C02-model-interaction.md#实验与收尾验收) | 外层响应成功解析，content 却是普通句子；或者业务字段全部合格，引用却不支持答案。分别在哪一层发现？ | 能区分响应、回答文本与业务对象；能说明格式或字段检查的边界，并对应实验观察项 |
| [C03](../lessons/C03-tool-calling.md#实验与复盘) | path 是字符串，目标却在允许目录外；或者工具成功了，但结果消息使用另一次调用的 ID。还缺哪些检查？ | 能说明参数模式不保证权限、ID 用于对应请求；指出函数行为与消息接线要分别验证 |
| [C04](../lessons/C04-agent-loop.md#第五段用轨迹验证循环) | 工具额度已用完，模型请求次数仍有余额；下一轮可能返回文本，也可能再次请求工具。两种情况如何处理，记录什么？ | 能分开两种次数，并说明检查发生在动作之前；能够用轨迹判断停止原因，知道正常结束仍需核查内容 |

判断用“能独立解释 / 提示后能解释 / 仍有困难 / 未检查”，附原始回答与依据，不仅记录满意度。不能因为读者刚复述过示范答案，就认定其已经会独立实现。

## 测后纠错的检查

使用 [公共纠错示例](../../prerequisite-baseline-quick-check.md#测后反馈与纠错示例) 检查反馈是否包含：成立的部分、具体误解、机制与原因、例子或反例、可追问方向及新情形复核。若实际答案并无正确部分，不强行寻找可夸奖之处，直接说明需要从哪里建立认识。

首次评分保持原样。根据学习者真实缺口选一处反馈，不机械套用完整示例或一次重讲全部基础。解释和理解检查计入原课内时间；原始答案、提示及复核分开记录。

## 记录与后续修改

具体试读记录保存到被 Git 忽略的 `.local/lesson-readthrough/`；涉及基础知识的个人诊断追加到本地 baseline-status.md。每次记录日期、讲义版本、已知前置条件、实际阅读片段、卡住的词句、原始解释、提示与复核结果、实际耗时及下一步。未知信息写未知。

公共进度只记录材料修改和试读状态，不复制个人答案、成绩或诊断。发现问题时说明哪段缺少前置解释、哪个例子没有连接实验、哪个步骤无法判断结果，再修改相应段落；增加字数本身不作为改进证据。
