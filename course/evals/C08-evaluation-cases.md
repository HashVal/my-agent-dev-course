# C08：评测集与评分器验收

问题见 [tasks](../labs/C07-workflows/tasks.json)，事前标准见 [expectations](C08-expectations.json)，使用方式见 [lab](../labs/C08-evaluation/README.md)。标准不是模型输入。E08–E10 是公开预留案例，已用于调试后不可继续称为独立检查。

## 评分器校准

至少核查：格式错误不能通过；伪引文不能通过；正确引文配错误结论在没有语义核查时为 pending、核查错误后为 fail；未运行任务保留 not_run。人工 correct=true 不覆盖运行或字段错误。摘要行必须能追溯到对应日志与复核。

## 任务评分口径

answerable、必要文件与 facts 共同定义每题要求。正确回答应满足全部事实，没有不支持的附加结论，引用逐字存在且适用于相应任务。资料不足题要求 answer=null、说明具体缺口，不编造数字；相关引用允许为空，但已有引用仍需真实且不误导。

`required_files` 的机器检查仅覆盖固定语料的来源齐全；语义仍人工检查。不要求固定措辞或唯一行动路径。意见不明确时记录待审及理由，不强行取一个分数。

## 结果比较与局限

all 与 agent 各十个计划位置，逐题保存通过/失败/待审/未运行；source 不同的结果分开汇总。请求次数、实际工具尝试、耗时与 usage 按同题对照，不只报告成功样本的成本。费用未知为空。

解释至少一个根因判断：区分证据缺失、生成推断、参数/权限、协议、预算或环境故障，并说明证据不足的地方。没有运行的检查不写已验证；本课堂小样本不能代表普遍可靠性。
