# C10：综合验收依据

与 [讲义](../lessons/C10-capstone.md)、[lab](../labs/C10-capstone/README.md) 一起使用。以下是公共验收约定，个人判定留在本地。

| 范围 | 证据 | 未完成时如何记录 |
| --- | --- | --- |
| 核心运行 | 一条从问题到工具反馈再到答案的完整轨迹；参数、ID、预算符合约定 | 指明断在模型、工具、消息或停止层 |
| 答案与证据 | 同题的结构、来源、语义核查，不能仅展示 completed | 格式通过但事实待审要分别记 |
| 比较基线 | all 与 agent 十题计划的记录及评分，来源一致 | 缺项保留 not_run；模拟为 simulation_only |
| 失败分析 | 至少一份可定位的失败，现象/证据/假设/改动/验证/限制分开 | 未证明的原因写假设，未复测写待验证 |
| 复现与版本 | 运行步骤、环境、模型配置、预算、文件指纹；实际复跑一条任务 | 仅列命令未执行不能算已复现 |
| 理解与边界 | 解释模型和程序职责；在新情形中定位限制 | 记录独立解释、提示后解释或未检查 |

`audit.py` 只做材料与文件一致性检查，不自动评定学习者。核心功能通过、仍有已分析且边界明确的失败可以作为课程结果；核心实现无法运行或验收证据缺失时不能宣布全部完成。

不能由本课推出生产可靠性、完整沙箱、长期恢复能力、多 Agent 能力或已复现论文。下一步建议应对应实际失败，不以新框架数量代替改进证据。
