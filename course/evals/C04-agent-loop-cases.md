# C04 验收参考：反馈循环与停止状态

配合 [讲义](../lessons/C04-agent-loop.md) 与 [实验说明](../labs/C04-agent-loop/README.md)。下列为公共测试规格与评分表，不包含个人成绩或真实模型输出。

## 离线控制流

[check_loop.py](../labs/C04-agent-loop/check_loop.py) 使用明确标注的模拟模型与工具。计数分别是模型请求尝试数、工具分发尝试数，失败尝试也计入；不是 token 数或成功读取次数。

| 编号 | 人工输入与预算 | 必须观察到的行为 |
| --- | --- | --- |
| L01 | 连续两个合法工具请求，然后最终文本；默认预算 4 / 3 | completed，3 次请求、2 次分发。每轮保留全部历史；前轮快照不随列表追加而改变。 |
| L02 | max_steps=0 | max_steps，0 次请求、0 次分发。 |
| L03 | 模型持续提出调用；max_steps=2、max_tool_calls=3 | max_steps，2 次请求、2 次分发；最后工具结果保留，不增加总结请求。 |
| L04 | 模型持续提出调用；max_steps=4、max_tool_calls=1 | max_tool_calls，2 次请求、1 次分发；被阻止的第二个请求保留在原始响应中。 |
| L05 | 工具额度为 0，模型直接回答或请求工具 | 直接回答可 completed，1 / 0；请求工具则 max_tool_calls，1 / 0。 |
| L06 | max_steps=2、max_tool_calls=1；一次读取后在最后一步回答 | completed，2 / 1；不能因达到边界而丢弃最终回答。 |
| L07 | max_steps=1、max_tool_calls=1；唯一模型响应要求工具 | max_steps，1 / 1；只有读取结果，answer=None。 |
| L08 | 工具返回 ok=false，模型随后回答；或反复请求失败工具 | 错误结果进入下一轮并消耗额度；不能把失败次数漏计，也不能由程序伪造业务答案。 |
| L09 | 替身模型读取工具结果中的 next_path，再选择后续文件 | 改变反馈时，第二个调用参数随之变化；程序执行模型提出的路径，不硬编码文件顺序。仅证明接线机制。 |
| L10 | 多个 choices、多工具批次、length、空最终文本、缺 ID 或结束原因与内容冲突 | protocol_error；一轮请求已计数，分发 0 次，原始响应保留。 |
| L11 | 工具结果 ID 错配，或后续响应重复已使用的调用 ID | protocol_error；停止继续请求或重复分发，保留已有执行尝试。 |
| L12 | 请求超时，或执行器抛出 OSError | 分别 model_error / tool_exception，不自动重试；请求与分发尝试数不回退。 |
| L13 | 预算为负数、布尔值或非整数 | 在请求前拒绝参数。 |

每条路径应有明确停止状态，未正常完成时 answer=None。额度用尽后尚未执行的调用只保留在 trace，不向消息历史追加一个没有对应工具结果的调用。若执行器本身异常，历史中可能留下未配对的调用，但记录必须失败并停止，不自动复用为后续请求。

公共骨架故意没有 run_loop 实现；未填写时测试失败是预期行为。离线控制流通过不证明真实模型能正确使用工具或回答问题，也不替代 C03 的文件边界验证。

## 真实任务与业务评分

接口和预算允许时，只运行一次 E02 任务。问题及原始资料沿用 [C01-E02](C01-baseline-cases.md#c01-e02组合两份资料)，本课评分标准不得放入模型输入。

| 维度 | 通过依据 |
| --- | --- |
| 控制流 | 每次请求携带完整、配对的历史；累计请求与分发均不超过设置上限；停止状态与最后事件一致。 |
| 结论 | 说明虚构任务 T01 已执行 2 次，尚未达到 3 次上限。 |
| 证据 | 引用 trace.md 的任务调用记录、limits.md 的额度及计数规则；引文真实存在并支持结论。顺序和措辞不要求固定。 |
| 运行与业务边界 | completed 仍需核查内容；max_steps/max_tool_calls 是受限停止，不是“资料不足”的同义词。 |
| 比较范围 | 保存当前结果与 C01 基线的条件差异；不由一次运行认定 Agent 更好、更省或普遍可靠。 |

模型直接回答却缺少可核对的来源，可能正常结束但不满足业务验收；模型读了资料仍答错，也应如实记录。没有真实接口则该部分写“未验证”，不使用模拟答案代替。

## 理解检查与本地记录

收尾沿一条正常轨迹和一条受限停止轨迹，解释模型选择、程序执行、反馈进入输入、计数与终止。重点核对：

1. 为什么 while 代码固定，并不意味着工具顺序固定？
2. 为什么工具额度用完仍可能完成回答，而模型步数用完不能再发总结请求？
3. 未知工具被分发器拒绝，工具分发次数与真实文件读取次数分别如何计算？
4. 最终文本生成完成，还缺哪些业务核查？
