# C03 验收参考：调用、执行与结果关联

配合 [讲义](../lessons/C03-tool-calling.md) 与 [实验说明](../labs/C03-tool-calling/README.md)。这是公共验收标准和空白记录表，不是实际模型运行结果。测试只使用虚构资料或临时目录中的无害文件。

## 离线检查

[check_tool.py](../labs/C03-tool-calling/check_tool.py) 用标准库 unittest 检查以下行为。公共骨架的两个 TODO 尚未实现，直接对它运行会失败；填写本地副本后再验收。

| 编号 | 输入或场景 | 通过条件 |
| --- | --- | --- |
| T01 | 正常根目录文件与子目录文件 | ok=true，content 与原始 UTF-8 全文相同，file 为规范化相对路径。 |
| T02 | 错工具名、无法解析的 arguments、缺字段、错类型、空白、NUL、额外 root 参数 | 返回对应 unknown_tool 或 invalid_arguments，阅读函数未执行。 |
| T03 | 绝对路径、`../`、含 `..` 但最终仍在目录内的路径 | forbidden_path；没有原文或主机绝对路径泄漏。 |
| T04 | 文件及目录符号链接指向目录外，且外部目录共享相同文本前缀 | forbidden_path，不接受字符串前缀判断。目录内符号链接可读，来源为规范化目标。 |
| T05 | 不存在文件、名字以 .md 结尾的目录、非 .md 文件 | 分别返回 not_found、invalid_file、invalid_file。 |
| T06 | 刚好 4096 字节、超出一个字节、字符未超但 UTF-8 字节超限、非法 UTF-8 | 边界内成功，超限 too_large，非法编码 invalid_encoding；错误时不返回部分原文。 |
| T07 | 成功或失败的一次调用 | 消息顺序为 system、user、assistant、tool；tool_call_id 匹配，content 为可解析的业务 JSON 字符串。 |
| T08 | 无调用、length 截断、缺少调用 ID、一次返回两个调用 | 停止并保留错误；在校验失败前没有执行阅读函数，不伪造结果关联。 |

结合代码检查读取是否有界：仅验证大文件被报错，不能证明它没有先把整个文件加载进内存。路径测试面向静态 Linux 目录；测试通过不等于防住了并发文件替换或获得完整 OS 沙箱。

## 模型接线观察

接口可用时最多运行 clear/vague 各一次。只有第一轮调用与本地执行，不检查最终问答，因为本实验尚未发送工具结果后的第二次模型请求。

| 项目 | 检查方法 |
| --- | --- |
| 输入 | 第一次请求含目录信息、问题、工具定义，没有三份原文和评分答案。 |
| 调用 | 从真实 response 核对结束状态、工具名、参数和 ID；不拿 demo 冒充模型调用。 |
| 执行 | 用工具结果对照本地资料，失败时保留结构化错误。 |
| 关联 | next_messages 保留原 assistant 调用消息，并追加匹配的 tool 结果。 |
| 描述差异 | 固定其他请求内容与实现，只比较 description；报告实际观察，不从两条结果推断普遍成功率。 |

没有 API 或未运行对照时，分别标注“真实模型未验证”“只做静态比较”。API 返回文本而没有调用是观察到的行为；程序拒绝处理不等于网络或接口故障。

## 理解检查

1. 模型请求 `read_document({"path":"limits.md"})` 与 Python 实际读取之间，还需要哪几层程序处理？
2. 参数 JSON 合法、Schema 合法、文件在允许目录内、内容支持最终答案，是同一个判断吗？
3. `not_found` 与“原文没有回答所需信息”为什么不能互相替代？
4. 调用 ID 缺失或一个响应有两个调用，本课为什么不能自行补一个 ID 或只执行第一个？
5. 把工具结果加入本地 messages 后，模型是否已经看见？继续请求和循环停止分别由谁控制？

能用代码和运行记录说明以上分工，并通过正常与拒绝路径检查，构成本课核心证据。教师演示、学习者独立实现和真实模型观察分别记录，不以一个测试总数替代理解判定。
