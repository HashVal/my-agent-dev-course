# C02：结构化输出验收参考

本文件配合 [C02 实验](../labs/C02-structured-output/README.md) 与 [讲义](../lessons/C02-model-interaction.md)。只包含公共任务、判定标准与空白记录，不包含任何学习者的输出或成绩。先确定标准，再运行模型；本文件不加入被测模型输入。

## 数据与任务

沿用 [C01 三题](C01-baseline-cases.md) 的问题、三份虚构资料及内容评分要求。每题独立发送一次，改变输出形态为业务 JSON；不能因为格式改变而放宽事实、引用或缺口要求。

| 用例 | 结构化行为 | 仍须核对的任务要求 |
| --- | --- | --- |
| E01：工具调用上限 | answerable=true，answer 非空，missing_information=[]，citations 非空。 | 上限与 limits.md 匹配，文件名和原文引用正确。 |
| E02：T01 是否达到上限 | 同上；允许结合多份资料推导。 | 解释已用调用与上限的关系，引用 trace.md 和 limits.md 的相应依据。 |
| E03：T01 的费用 | answerable=false，answer=null，missing_information 为非空字符串数组。 | 不捏造金额；说明费用信息缺口，引用已有相关记录说明资料范围。费用缺口接受等价表述，详见 C01 规则。 |

四个字段必须存在；citations 的每项含非空非纯空白的 file、quote，missing_information 的每项也须非空非纯空白。字段与跨字段约定详见 [实验数据约定](../labs/C02-structured-output/README.md#数据约定)。

一般任务在不可回答且没有相关资料时，可以没有引用。当前三个问题均有相关资料；E03 的空引用可能通过结构校验，仍不满足本用例来源要求。不得把“语法正确”或“请求成功”计作完整任务通过。

## 离线检查与人工反例

以下是可选取的测试设计，不是模型实际返回。至少覆盖两个正常分支和两个异常组合；在本地作答副本调用 parse_answer 或校验函数观察结果，不发送 API 请求。

| 检查 | 预期及解释 |
| --- | --- |
| 两种正常组合 | 可回答时有非空答案且缺口数组为空；不可回答时答案为 null 且缺口具体。分别通过程序约定。 |
| 空白答案或分支冲突 | 可回答却给空白答案，或不可回答却给确定答案，应被一致性检查拒绝。 |
| 缺口数组错误 | 不可回答时缺口为空、类型错误或条目纯空白，应在相应层被拒绝。 |
| 引用对象错误 | 缺少 file/quote、条目不是对象、引文纯空白，应被字段检查拒绝。 |
| 结构正确、结论矛盾 | 手工把答案写成最多 30 次，保留 limits.md 中最多 3 次的引文及其他合法字段；预测结构与引文存在性检查能否发现错误，再与原文核对。 |
| 结束原因异常 | 教师可注入 finish_reason=length 与截断 content 的模拟响应，检查保存顺序、非零退出和无自动重试；不得伪装成真实模型运行。 |

程序检查通过只说明检查范围内的条件成立。当前骨架允许额外字段，也不检查文件名是否来自给定资料、引文是否存在、证据是否支持结论或是否遗漏相关依据；这些限制须在判定中写清楚。
